# kompas_lib — автономный выпуск (КОМПАС-3D v26 + KsAPI)

Подключение: `import sys; sys.path.insert(0, r"<эта папка>")` → `from kompas_lib import Kompas` → `k = Kompas.connect()`
(КОМПАС установлен; `ksapi.py` и нативная библиотека берутся из него, ставить ничего не нужно).
Поиск — сначала `rg -i "своё слово" llms.txt` (в строках задач есть синонимы: «плотность», «МЦХ», «фаска под углом»,
«круговой массив»…), и только потом `kompas_lib.py`, `ksapi.py` или SDK.
Карта API — `llms.txt`: `rg "^task" llms.txt` — задачи с цепочками вызовов; `rg "^type\tkompas_lib.model.Face"` —
откуда тип и куда его передавать; определение открывается по полю «файл:строка» (`kompas_lib.py:22978`).
Весь код — `kompas_lib.py` (монолит с настоящими модулями `kompas_lib.build`, `kompas_lib.dims`, `kompas_lib.drawing`…).
Правила: изменения документа — только внутри `with doc.edit():`; чужие модели — `k.open(path, read_only=True)` и
`close(save=False)`; свои — `k.new_part(tag="…")` → следующий скрипт `k.find("…")`, эксперимент —
`with k.scratch_part() as doc:`, уборка — `k.close_tagged(…)` (не закрывать `k.documents` скопом — там документы
пользователя); результат смотреть глазами — `Document.capture()` / `render_model()` → PNG.
Деталь по PDF-чертежу: 1) номиналы — из надписей (`read_pdf_drawing` → размеры; текст точнее линий);
2) чего нет в размерах (центры, касания, R без размера) — `pdf.views()` → `view.geometry()` (мм модели от
левого нижнего угла вида): не писать свой разбор PDF, не сканировать пиксели; 3) сразу строить и сверять
`render_model()` с видами, уточнять по расхождениям. Мелочь без размера — оценить один раз и строить;
~15 вызовов без операции в КОМПАСе — хватит читать, строй.
`grep -P` в консоли Windows падает («supports only unibyte and UTF-8 locales») — искать `rg` или `grep -E`.
