# Анализ набора «чертёж — модель»

## Кратко

[Ноутбук](EDA.ipynb) исследует состав и качество датасета: комплектность, точные
повторы, изображения листов, эталонную геометрию и известные различия пар.
Дополнительно показано, как уменьшение изображения меняет размер содержащихся
в нём деталей и надписей. Все текущие объекты — рабочая валидация, а не независимый тест.

Изображения, таблицы и выводы сохранены в ноутбуке и доступны без запуска Jupyter.
Связь результатов EDA с требованиями к системе описана в
[дизайн-документе](../docs/ml_system_design_doc.md).
Код baseline и план его проверки описаны в [README проекта](../README.md#baseline).
Результаты генерации будут добавлены на следующем этапе.

## Окружение

EDA использует отдельное окружение `notebooks/.venv` на Python 3.12.
Зависимости закреплены в [pyproject.toml](pyproject.toml) и [uv.lock](uv.lock).
Корневое окружение содержит baseline и инструменты проверок;
настройки Ruff для ячеек находятся в `notebooks/pyproject.toml`.
Для анализа готовых изображений и сеток не нужны КОМПАС, CadQuery и ключ API.

Из корня репозитория:

```bash
uv sync --project notebooks --locked
uv run --project notebooks --locked jupyter lab notebooks/EDA.ipynb
```

В Jupyter выберите Python этого окружения. В VS Code выберите интерпретатор
`notebooks/.venv/bin/python` (в Windows — `notebooks/.venv/Scripts/python.exe`).
При необходимости именованное ядро можно зарегистрировать в окружении:

```bash
uv run --project notebooks --locked python -m ipykernel install --sys-prefix --name kompas-eda --display-name "EDA и 3D (Python 3.12)"
```

## Воспроизводимая проверка

Из корня установите окружения проекта и EDA, затем выполните ноутбук:

```bash
uv sync --locked
uv sync --project notebooks --locked
uv run poe eda-check
```

Для полной проверки, включая код и тесты baseline, Ruff и форматирование, используйте
`uv run poe check`. Настоящая модель при этом не вызывается. Линт и форматирование
также настроены для ноутбуков в pre-commit.

Команда выполняет все ячейки и сохраняет результат в
`artifacts/mlsd/EDA.executed.ipynb`, не перезаписывая исходный ноутбук.
Результат проверки игнорируется Git; в репозитории остаётся читаемая версия EDA
с сохранёнными таблицами и графиками. Во время анализа сетевые запросы не выполняются.

## Данные и ограничения

Ноутбук читает [PNG](../data/input), [эталонные STL](../data/target)
и [манифест датасета](../data/manifest.json) — список пар чертежей и моделей
с путями к файлам и метаданными. Перед анализом сверяются контрольные суммы.
PNG здесь — изображение исходного чертежа, STL — представление эталонной геометрии
для исследования. Эти форматы не ограничивают источники документации и конечный
результат будущей системы для КОМПАС.

Исходные файлы не изменяются. Локальный архив и исходные CDW/M3D для анализа не нужны.
Проверки хешей и сеток не заменяют экспертизу соответствия чертежу. Известные различия
пар, преобладание одного источника и отсутствие независимого теста обсуждаются в выводах.
Уменьшение до 4096 пикселей соответствует начальной настройке baseline;
его достаточность для MVP ещё нужно проверить на значимых надписях и размерах.
