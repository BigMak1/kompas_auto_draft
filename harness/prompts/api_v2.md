# API построителя

## Кратко

`kompas-builder.build` принимает `{"recipe":{"steps":[...]}}` и строит новую деталь в КОМПАС.
Это ограниченный адаптер над `kompas_lib.PartBuilder`, а не выполнение Python-кода.

## Рецепт

Перед первым build вызови `health` с `{}`. Ожидается успешное read-only подключение к
КОМПАС и `build_quarantined: false`. Порядок подключения — в `CONNECTION.md`.

Каждый шаг содержит `op`, уникальный `id` (`[a-z][a-z0-9_]{0,39}`) и параметры из таблицы.
Ссылки допускаются только на предыдущие шаги нужного типа. Плоскости `XY`, `XZ`, `YZ` встроены.
`id` используется как имя операции. У каждого шага дополнительно разрешено поле `bindings` (ниже). Остальные поля запрещены.

| op | Обязательные параметры | Дополнительные параметры |
|---|---|---|
| `offset_plane` | `base`, `offset` | `reverse` |
| `sketch` | `plane`, `items` | `constrain` |
| `extrude` | `sketch`, `depth` | `reverse`, `depth2`, `symmetric`, `draft` |
| `cut` | `sketch` | `depth`, `reverse`, `depth2`, `symmetric`, `through`, `draft` |
| `revolve` | `sketch` | `angle`, `cut`, `reverse`, `angle2` |
| `fillet` | `edges`, `radius` | `chain` |
| `chamfer` | `edges`, `distance` | `distance2`, `angle`, `chain` |
| `circular_pattern` | `steps`, `axis`, `count` | `angle` |

`edges` — индексы рёбер текущей детали. Для их получения построй рецепт без финальной фаски,
посмотри `edges` в ответе, затем повтори тот же рецепт с добавленным шагом. Индексы нельзя
переносить между разными геометриями. `steps` массива — список ID операций; `axis`: X/Y/Z.
Индексы упорядочены по геометрии ребра. Если ответ содержит `edges_truncated: true`,
описания рёбер могут отсутствовать. Для фасок и скруглений подбери рёбра на более простом
префиксе рецепта, например до кругового массива.

`items` эскиза — список объектов `{"type":"...","args":[...],"style":"normal"}`:

| type | args |
|---|---|
| `line` | `[x1,y1,x2,y2]` |
| `circle` | `[xc,yc,r]` |
| `arc` | `[xc,yc,r,a1,a2]`; дополнительно `ccw: true/false` |
| `rect` | `[x1,y1,x2,y2]` |
| `polygon` | `[[x1,y1],[x2,y2],...]`, замыкается автоматически |

`style`: `normal`, `axis`, `construction`; по умолчанию normal.
Для вращения нужна линия `style: "axis"`. Основной контур замкнут; библиотека проверяет его.
Направления эскизов из справочника библиотеки: XY: x→+X, y→+Y, нормаль +Z;
XZ: x→+X, y→−Z, нормаль +Y; YZ: x→−Z, y→−Y, нормаль −X.
`reverse` меняет направление операции относительно нормали.

Пример протокола, не решение входного задания:

```json
{"recipe":{"steps":[
  {"op":"sketch","id":"profile","plane":"XY",
   "items":[{"type":"circle","args":[0,0,10]}]},
  {"op":"extrude","id":"body","sketch":"profile","depth":15}
]}}
```

Вызов возвращает `attempt`, `status`, параметры полученной модели, отчёт и PNG.
При `status: built` можно вызвать `finish` с `{"attempt": <номер>}`. После finish окончательная
M3D сохранена доверенной частью запуска. Это ещё не результат сравнения с эталоном.

`view_input` без аргументов возвращает лист; `{"crop":[x,y,width,height]}` — фрагмент в пикселях
от левого верхнего угла. Этот инструмент всегда читает только исходный PNG.

## Управляющие размеры и переменные: API v2

Корень рецепта принимает `variables` — упорядоченный список объявлений:
`{"name":"outer_d","value":20,"note":"Наружный диаметр"}`.
Значение — число или `{"expr":"outer_d/2"}` с уже объявленными переменными.
Имена: `[a-z][a-z0-9_]{0,31}`; имена вида `v12` и `d0` зарезервированы.
До 40 переменных; `note` до 160 символов. Повторы, неизвестные имена и циклы запрещены.

Любое число в координатах и параметрах операции можно заменить на `{"expr":"..."}`.
Разрешены числа, имена объявленных переменных, `+ - * /`, унарный минус и скобки.
Функции, степени и произвольный код не поддерживаются. До 160 символов в выражении;
модуль каждого промежуточного результата не больше 100000. `count` должен дать целое 2..100.

**Выражение в координатах только вычисляет начальную форму.** Для редактирования готового
M3D нужны нативные управляющие размеры и привязки:

- `constrain: true` у эскиза создаёт размеры и геометрические связи через библиотеку.
  Лимит — 16 развёрнутых элементов: `rect` считается за четыре линии, `polygon` — по вершинам.
  Результат включает фактическое состояние `defined / under / redundant / unknown`,
  принятые размеры и отклонённые ограничения. Полная определённость не гарантируется.
- `bindings: {"d0":"outer_d"}` у такого эскиза связывает принятый размер с переменной.
  `d0`, `d1`, ... — порядок размеров из `parametric.steps.<id>.dimensions`, начиная с нуля.
  Посмотри описание размера; после изменения структуры эскиза соответствие надо проверить заново.
- `bindings: {"Расстояние 1":"thickness"}` у операции связывает её настоящий параметр.
  Селектор — имя `vN` или однозначное название параметра из `parameters` в ответе моста.
  Названия могут зависеть от установленного КОМПАС; не придумывай их.
- Значение выражения должно совпадать с начальным размером выбранного параметра.
  Несовпадение вызывает ошибку, чтобы неверная привязка не искажала деталь незаметно.
  Выражение `bindings` должно использовать объявленную переменную.

Пример параметризованного цилиндра, не решение задания:

```json
{"recipe":{
  "variables":[
    {"name":"outer_d","value":20,"note":"Наружный диаметр"},
    {"name":"thickness","value":10,"note":"Толщина"}
  ],
  "steps":[
    {"op":"sketch","id":"blank_profile","plane":"XY","constrain":true,
     "items":[{"type":"circle","args":[0,0,{"expr":"outer_d/2"}]}],
     "bindings":{"d0":"outer_d"}},
    {"op":"extrude","id":"blank","sketch":"blank_profile","depth":{"expr":"thickness"},
     "bindings":{"Расстояние 1":"thickness"}}
  ]
}}
```

В ответе `parametric.variables` — переменные детали, `parametric.steps` — параметры шагов,
принятые привязки и состояние эскизов; `unused_variables` — переменные без использования в CAD.
Поле `raw` native-объектов не выдаётся. Для `dN` показано начальное значение; актуальное значение
и формулу смотри в `parameters` по соответствующему имени `vN`.

Если селектор неизвестен, сделай build без его bindings, изучи возвращённые параметры,
добавь привязку и повтори полный рецепт. Каждая попытка строит новую деталь; API не редактирует
произвольные существующие документы. Проверка изменения сохранённого M3D выполняется отдельно
оценщиком на копии, а не по одному только наличию переменных.

## Ограничения адаптера

Не все функции библиотеки доступны через мост. Например, произвольный доступ к KsAPI,
импорт файлов, работа с чужим документом, сплайны, резьба и произвольные булевы операции
этим протоколом не реализованы. Отверстия можно получить вырезами. Лимиты: до 100 шагов,
до 1000 элементов в эскизе, до 30 попыток. Числа должны быть конечными, |x| ≤ 100000.
Выход проверяется на положительный объём и одно тело; это не полная проверка валидности B-rep.
При таймауте Windows дальнейшее построение блокируется до проверки оператором.
