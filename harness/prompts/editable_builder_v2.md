# Построение редактируемой детали по изображению

## Кратко

Построй 3D-деталь КОМПАС-3D по единственному входу `input/drawing.png`.
Нужны правильная геометрия и понятное дерево, в котором человек может отдельно менять
основную форму, отверстия, пазы, фаски и скругления. Результат — M3D через
`kompas-builder.finish`, окончательный `work/recipe.json` и `work/report.md`.

Версия инструкции: `editable_builder_v2`. Эта инструкция применяется к новому прогону;
доступные инструменты и поля рецепта определяет его `API.md`.

## Подключение и исходные данные

Перед построением прочитай `CONNECTION.md` и `API.md`. Проверь настоящие MCP-инструменты чата:
`ksapi-expert.search` и `kompas-builder.health`. Не запускай мост через subprocess в shell.
Справочник библиотеки — `library/llms.txt`, код — `library/kompas_lib.py`.
Наличие функции в библиотеке не означает, что она доступна через ограниченный MCP.

Рассмотри весь PNG и нужные участки через `kompas-builder.view_input`.
Размеры и виды бери только из этого изображения; единицы — мм и градусы.
Неизвестные размеры и форму явно обозначай как допущения, не выдавай их за прочитанные.

## Структура модели

1. До построения запиши в `work/model_plan.md` основные элементы детали и предполагаемое дерево.
   Для каждого элемента укажи операцию, исходный размер или допущение и параметр,
   который инженер должен иметь возможность изменить.
2. Создавай основную форму штатными операциями `extrude` или `revolve`.
   Для отдельного отверстия или паза используй отдельный `cut` со своим простым эскизом.
   Предпочитай естественное конструктивное разбиение; не минимизируй число операций любой ценой.
3. Стандартные фаски оформляй отдельными `chamfer`, скругления — отдельными `fillet`.
   Не прячь независимо изменяемые фаски и радиусы в координатах большого эскиза.
   Если операция не проходит, сначала проверь выбор рёбер и порядок построения.
   Если ограничение моста не удалось обойти, сохрани лучший результат и явно перечисли
   встроенные в эскиз элементы как ограничение редактируемости.
4. Повторяющиеся элементы строй как один элемент и `circular_pattern`.
   Число повторений должно изменяться параметром массива, а не ручным копированием контуров.
   Используй другие виды массивов только при их наличии в API конкретного запуска.
5. Эскиз должен описывать одну понятную конструктивную задачу. Для окружностей и прямых
   используй соответствующие примитивы. Полигон допустим для настоящего ломаного профиля;
   не заменяй им окружность или стандартную фаску ради упрощения рецепта.
6. Для функционального сложного профиля, например зуба, допустим отдельный расчётный эскиз.
   Отличай форму профиля от технологической фаски: не заменяй эвольвенту или её переход
   произвольным скруглением. Запиши исходные параметры профиля, способ аппроксимации
   и ограничения его изменения в готовом CAD.
7. Давай операциям осмысленные уникальные `id`: например, `blank`, `bore`, `keyway`,
   `outer_chamfer`, `bore_chamfer`, `keyway_fillet`, `tooth_space`, `teeth_pattern`.
   Соблюдай ограничения имени из `API.md`; мост использует `id` как имя операции.
8. Выбирай порядок операций так, чтобы сохранялись их смысл и устойчивость ссылок.
   Фаску заготовки можно выполнить до сложного зубчатого массива, если так получается
   требуемая геометрия. Не требуется механически ставить все фаски в самый конец.

## Параметры и ограничения инструментов

Цель — возможность менять ведущие размеры в самом КОМПАС: диаметр отверстия,
ширину паза, толщину, фаску, радиус, число повторений. Запись этих чисел в JSON или отчёте
сама по себе не создаёт параметров CAD.

В этом запуске API v2 предоставляет `variables`, `constrain: true` и `bindings`.
Объявляй основные размеры именованными переменными с понятными `note`.
В простых эскизах включай `constrain: true`, связывай ведущие размеры `d0`, `d1` и т. д.
с переменными. Глубину, радиус и другие параметры операции связывай через её `bindings`.
Проверяй реальные имена и смысл параметров в `parametric.steps` ответа моста.
Сначала допустим диагностический build без bindings, чтобы увидеть доступные размеры;
затем добавь связи и повтори полный рецепт. Не угадывай соответствие `dN` и геометрии.

`{"expr":"width/2"}` в координатах вычисляет начальную геометрию. Постоянная связь в M3D
возникает только через `bindings` к управляющим размерам либо через выражения самих переменных.
Проверяй `state`, `auto_constraints.rejected`, `parameters`, `bindings` и `unused_variables`.
Состояние `defined` само по себе не доказывает удобство редактирования; фиксация всех точек
не заменяет размеры и конструктивные связи. Переменная без связи с геометрией не считается
реализованным редактируемым размером. Удаляй ненужные переменные или явно объясняй ограничение.

Автоограничения доступны для простых эскизов (см. лимит API). Для сложного профиля используй
отдельный эскиз, `constrain: false` и укажи, какие изменения требуют повторной генерации рецепта.
Не обещай, что изменение числа зубьев автоматически пересчитает неподвязанный профиль.
Геометрические допущения и ограничения параметризации отмечай раздельно.

Индексы рёбер относятся только к текущей геометрии. Получай их из построения того же префикса
рецепта; после изменений заново проверяй. При `edges_truncated` не выдумывай отсутствующие индексы.
Не обходи ограничения чтением чужих документов или прямым доступом к Windows.

## Построение и результат

Передавай полный рецепт в `kompas-builder.build`. Каждый вызов строит новую собственную деталь.
Проверяй результат и исправляй рецепт при необходимости. Окончательную успешную попытку выбирай
через `kompas-builder.finish`. Сохрани её рецепт без последующих незапущенных изменений.

В `work/report.md` перечисли допущения, упрощения и непостроенные элементы. Добавь таблицу:

| Изменение инженера | Операция / эскиз | Что менять в КОМПАС | Подтверждение или ограничение |
|---|---|---|---|
| Диаметр отверстия | … | … | Размер доступен / только геометрия эскиза / не проверено |
| Толщина детали | … | … | … |
| Размер фаски или скругления | … | … | … |
| Число повторений, если есть | … | … | … |

Приводи только применимые к своей детали строки. Не называй изменение проверенным,
если доступный инструмент не выполнял редактирование и перестроение сохранённой модели.
Проверка конечной редактируемости выполняется оценщиком отдельно на копии M3D.
Паспорт JSON не обязателен. Самостоятельно искать эталон или считать сходство с ним запрещено.

## Границы

Рабочие записи разрешены только в `work/`. Вход и библиотека доступны только для чтения.
Пользовательские файлы вне рабочей папки, сеть, SSH, браузер, чужие документы и прогоны
недоступны. Не ищи исходную модель или обозначение детали в интернете.

Правила этой папки имеют приоритет над примерами библиотеки. Строй только через ограниченный
MCP: он подключается к запущенному КОМПАС и закрывает только собственный документ.
Произвольный Python в Windows, импорт моделей и открытие существующих CAD-файлов не разрешены.
Пути сохранения назначает мост; настройки запуска изменять нельзя.
